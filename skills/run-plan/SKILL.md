---
name: run-plan
description: Run a slice plan sequentially through subagents, reconciling blockers and escalating decisions it cannot make.
---

Orchestrate the plan to completion, asking for its path if none is given. Your work is dispatching subagents, routing their reports, talking to the user, and recording run state. Run state (status, baselines, landed revisions, the autonomy grant, and the decision index, kept in `state.json`) changes only through `plan`. You call `plan` directly for your own writes and reads, and dispatch subagents for every other change and for every inspection of repository state, implementation, verification, and reconciliation. `plan status` is the source of truth for the run's state, over anything this conversation remembers.

Below, `plan <command>` means `python3 <cli> --plan <dir> <command>`, where `<dir>` is the plan directory and `<cli>` is `../slice/bin/plan` resolved from this skill's directory to an absolute path. When that file is missing or lacks a command used here, stop and report that `slice` must be installed or updated beside this skill. `plan <command> --help` documents each command.

## Inspect

When the plan directory has no `state.json`, run `plan import <dir>` before anything else; if the import fails, stop and report its error.

Read `plan status --json`. Its `eligible` slices can start. An **interrupted** slice is one without a worktree that is in progress, or blocked with a recorded fixed point; a slice with a worktree is not this skill's to run, so report it. Continue an in-progress slice before starting another; a blocked one continues once what its reason names is resolved. An interrupted slice goes to a fresh worker with the **recovery report**: before dispatching it, have an inspection subagent check the repository state against `checkpoints/<ID>.md` and report the slice's recovery state.

## Run each slice

Dispatch a fresh **worker** per slice with the plan path, slice ID, relevant user decisions, any recovery report or existing `checkpoints/<ID>.md` (`plan status` names a paused slice's), and the absolute path of `../next-slice/SKILL.md`, relative to this skill's directory. `next-slice` is manual-only, so instruct the worker to read that file directly instead of invoking it as a skill, resolve its relative links from its directory, and follow it for that slice alone. Tell it to return to you, instead of asking the user or handing back to `slice`, every unresolved blocker and every consequential choice `next-slice` would settle with the user.

A worker that dispatches its own reviewers waits for every reviewer's report before returning. One that cannot delegate further returns each subagent assignment it needs, such as `code-review`'s reviewers, with its context, as a request, so review stays independent; its slice stays in progress, and the request is not the slice's outcome. Dispatch those, sequentially if capacity requires, dispatching a reviewer that is lost or returns no report again with the same assignment, and continue that same worker only to return each reviewer's report to it unedited. A lost worker leaves interrupted work, which a fresh worker continues through `next-slice`'s RECOVERY, redoing any review that has no result.

Each worker returns its outcome, evidence, landed revision, and the next eligible slice or remaining blockers; a slice is complete once `plan status` shows it complete. Run slices sequentially: hand the workspace to another subagent only after the current worker returns. Then inspect again and dispatch a fresh worker for the interrupted slice or the next slice `plan next` lists, until every slice is complete or none can proceed.

## Blockers

The user may grant autonomy for the run. Record it with `plan grant --note <its terms>`. A grant that `plan status` already shows is the run's grant after a restart; record new terms with `plan revoke`, then `plan grant`. The grant lasts until the run completes, when you end it with `plan revoke`, or until the user revokes it, which you record the same way; every other stop leaves it recorded for the restart.

A **reconciler** investigates an issue against the plan, repairs within the plan when it can, decides plan changes under an autonomy grant, and otherwise returns an **escalation**: a concrete question, options, a recommendation, and the affected slices. Workers fix routine failures and review findings themselves, and a minor finding for `slice` stays in the worker's checkpoint, which `plan complete` folds into `log.md`. For an unexpected issue, an unresolved blocker, or a worker's finding for `slice` that would change a slice's scope or the plan, dispatch a reconciler with the report, the plan directory, the absolute path of `<cli>`, whether autonomy is granted, and the absolute path of [RECONCILER.md](RECONCILER.md), instructing it to read and follow that file. For each `R<n>` a reconciler decides, read its row in `plan decisions --json`; when `unfinished` names two or more slices, tell the user at once and keep running. A reconciler edits the slice files for a decision it makes under the grant and returns any change to `plan.md`'s prose, which you have a `slice` subagent apply as below, passing it as a revision the grant authorizes, with no approval step. After a repair or decision, a worker runs or reruns each unfinished slice it unblocks before you accept that slice as complete; the next final check verifies a repair outside any slice. Escalate a recurring unresolved blocker instead of repeating the same repair.

Relay escalations to the user and pause every slice an escalation lists as affected under any of its options. First run `plan block <ID> --reason <the input it awaits>` for each such slice that is ready or in progress. Then have a subagent record each paused slice's next action in `checkpoints/<ID>.md` (`plan start` keeps that file for a slice not yet started) and, for one that has started, preserve its recovery state and unverified changes and confirm it can be left safely; only then continue other eligible slices. Pass the user's answer to a reconciler: it records the answer with `plan decide`, updates the next action in `checkpoints/<ID>.md` of each paused slice the answer affects, and returns the approved revision without editing slice files or `plan.md`. Dispatch a subagent to read and follow `../slice/SKILL.md` directly, as workers read `next-slice`, and apply every slice-file and `plan.md` change of that revision, passing `--note "R<n>: <summary>"` to each `plan slice add|edit`, before dependent slices continue; one approved revision yields one `slice <ID> revised` entry per changed slice. Then return each paused slice that never started to ready with `plan resume <ID>`; a started one is interrupted work, which a fresh worker resumes.

## Finish

When `plan status` shows every slice complete, dispatch a subagent to check the agreed outcomes and required integration evidence, and route its gaps to a reconciler. Finish once the check finds no gaps, with a final report of the plan path, completed work, repairs that reconcilers reported outside any slice, and unresolved blockers. When nothing can proceed while input is pending, stop and report the paused state instead of completion; that stop keeps the grant.

After an autonomous run, meaning any run in which a grant was recorded, including one granted partway through, the report lists the `pending-review` decisions, costliest to undo first. `plan decisions --pending` gives the indexed ones in that order. When `log.md` has an ``imported by `plan import` `` entry, have a subagent report the `pending-review` decisions `log.md` records before it, which the index lacks, leaving out those a later `approved` decision names as the one it approves, and merge them in by their recorded undo cost. Then list the escalations that still await input.

For a completed run, assemble the final report; when a grant is recorded, run `plan revoke` before delivering it and say the grant ended.
