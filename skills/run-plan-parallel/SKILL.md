---
name: run-plan-parallel
description: Run a slice plan through parallel subagents in isolated worktrees, integrating each verified slice and reconciling blockers.
disable-model-invocation: true
---

Orchestrate the plan to completion, asking for its path if none is given, and run independent slices concurrently in isolated worktrees. Your work is scheduling, dispatching subagents, routing their reports, talking to the user, and recording run state. Run state (status, baselines, worktrees, scheduling constraints, landed revisions, the target tip, the autonomy grant, and the decision index, kept in `state.json`) changes only through `plan`, which serializes every write. You call `plan` directly for your own writes and reads, and dispatch subagents for every other change and for every inspection of repository state, implementation, verification, integration, and reconciliation. `plan status` is the source of truth for the run's state, over anything this conversation remembers.

Below, `plan <command>` means `python3 <cli> --plan <dir> <command>`, where `<dir>` is the plan directory and `<cli>` is `../slice/bin/plan` resolved from this skill's directory to an absolute path. When that file is missing or lacks a command used here, stop and report that `slice` must be installed or updated beside this skill. `plan <command> --help` documents each command. Give every subagent that runs `plan` the plan directory, the absolute path of `<cli>`, and this meaning of `plan <command>`. You may read the plan's prose to brief subagents.

Subagents writing prose keep to their own files: a worker writes only its worktree and its `checkpoints/<ID>.md`, an integrator only the slice files it updates, and a reconciler only the worktree it works in, the checkpoint of the slice it works in and of each paused slice an answer affects, and the slice files its repair or own decision changes. Slice files, `plan.md`, and the checkpoints of slices no worker is running are shared and unguarded by `plan`, so dispatch the subagents that write them, the **shared-prose writers**, one at a time: integrators, reconcilers, `slice` subagents, and the subagent recording paused slices' next actions. Workers, read-only subagents, and the inspection subagent run alongside them. While a `slice` subagent runs, no `plan` write runs, since each one rewrites `plan.md` around its status block: make none yourself and dispatch no subagent that makes one; while a reconciler that may write a slice's checkpoint runs, leave that slice unstarted. When a worker or integrator returns assignments because it cannot delegate further, its request is not the slice's outcome: dispatch them, sequentially if capacity requires, dispatching a reviewer that is lost or returns no report again with the same assignment, and return each reviewer's report unedited to that same worker or integrator. A lost worker or integrator leaves interrupted work, which the recovery report hands to a fresh one.

## Inspect

When the plan directory has no `state.json`, run `plan import <dir>` before anything else, adding `--target <branch>` when the user names a target branch other than the one `plan.md` records, and `--repo <root>` when `plan.md`'s Root is not the repository's path; if the import fails, stop and report its error. An imported plan keeps the target `plan status` shows; when the user names another, stop and report that the recorded target cannot change.

Read `plan status --json`. The user may grant autonomy for the run: record it with `plan grant --note <its terms>`. A grant that `plan status` already shows is the run's grant after a restart; record new terms with `plan revoke`, then `plan grant`. The grant lasts until the run completes, when you end it with `plan revoke` (Finish), or until the user revokes it, which you record the same way; every other stop leaves it recorded for the restart. A slice without a worktree that is in progress, or blocked with a recorded fixed point, was started in the repository checkout by `next-slice` or `run-plan`; report it and leave it to them, and while one is in progress, stop, since worktree slices start and land only on a clean target at the recorded tip.

Dispatch an inspection subagent to check the repository root and every slice that records a worktree, and to return the **recovery report**: for each in-progress slice with a worktree, whether its worker was interrupted, its commits await integration, or its integration was interrupted (a rebase in progress, or the target already holding its commits), with the worktree's state; and each complete slice whose worktree is still recorded, which needs only its removal. Require the repository root to be on the target branch at the recorded target tip, with no uncommitted changes outside the plan directory, since worktrees start from that tip and do not carry uncommitted changes. For uncommitted changes or another checked-out branch, ask the user to commit or set changes aside, or to use `run-plan`; when the target is ahead of the recorded tip by the branch of a slice that records a worktree, that slice's land stopped after its fast-forward: send it to its integrator first, then route any outside commits still beyond the recorded tip to a reconciler before other integrations.

Have it also flag unfinished slices likely to conflict if run at once (overlapping files, migration sequences, lockfiles, generated artifacts, or registries), and record each flagged pair, and each pair needing a resource that cannot be duplicated, with `plan constrain <A> <B> --reason <why>` as a **scheduling constraint**: two slices that never run at once, kept apart from the plan's dependencies. It skips pairs `plan status` already lists and pairs a dependency already keeps apart. For each unfinished slice it reports the resources its verification needs, such as ports, databases, or caches, as instances distinct from every other slice's. It also reports any contradiction it finds in the plan: send that to a reconciler (Blockers), and start no slice the contradiction affects until the reconciler returns.

## Schedule

Run up to three slices at a time unless the user sets another limit; a slice runs while it is in progress with a worktree, or while its worker is still running after a pause. Resume interrupted work first; then, whenever a running slice lands, or a paused slice stops running, start the next slice `plan next` lists, until every slice is complete or none can proceed. `plan next` omits slices constrained against a running slice, paused worktree slices included.

Start each slice with `plan start <ID> --worktree`, adding `--note <instance>` for each resource instance the inspection reported for it. It creates the slice's branch and worktree at the recorded target tip, which is the slice's base revision and fixed point, and `checkpoints/<ID>.md`; `plan status --json` gives the worktree's path, branch, base, and notes. When it refuses for uncommitted changes or another checked-out branch, ask the user as in Inspect; route any other refusal to a reconciler.

## Execute

Dispatch a fresh **worker** per slice into its worktree with the plan directory, the absolute path of `<cli>`, slice ID, worktree path, branch, base revision, resource notes, relevant user decisions, any recovery report, and the absolute paths of [WORKER.md](WORKER.md) and of `../next-slice/SKILL.md`, relative to this skill's directory. Instruct it to read and follow `WORKER.md`.

Each worker returns its outcome, evidence, slice-branch commits, checkpoint file, and any questions, blockers, or findings for `slice`. Integrate a committed slice; its integrator applies the downstream findings and pointer corrections in its checkpoint. Route questions, blockers, and findings that would change a slice's scope or the plan to a reconciler; minor findings stay in the checkpoint, which `plan land` folds into `log.md`.

## Integrate

When a worker reports a committed slice, or the recovery report shows commits awaiting integration, an interrupted integration, or a pending removal, dispatch an integrator with the plan directory, the absolute path of `<cli>`, the slice ID, the worker's report or the recovery report, and the absolute path of [INTEGRATOR.md](INTEGRATOR.md), instructing it to read and follow that file. Integrate one slice at a time, so each integrator rebases onto the tip the previous one landed; running slices stay on their base revision until their own integration. A slice is complete once its integrator's `plan land` lands it. Have a `slice` subagent apply the corrections to `plan.md`'s prose that an integrator returns, as an approved factual correction, with no approval step and no `--note`.

## Blockers

A **reconciler** investigates an issue against the plan, repairs within the plan when it can, decides plan changes under an autonomy grant, and otherwise returns an **escalation**: a concrete question, options, a recommendation, and the affected slices. Workers and integrators fix routine failures and review findings themselves; for an unexpected issue, an unresolved blocker, a contradiction in the plan the inspection subagent reports, a worker's question or findings for `slice`, an integration the integrator stopped, outside commits an integrator reports its land logged, or a refused `plan start`, dispatch a reconciler with the report, the plan directory, the absolute path of `<cli>`, the affected worktree, the running slices, whether autonomy is granted, and the absolute path of [RECONCILER.md](RECONCILER.md), instructing it to read and follow that file. For each `R<n>` a reconciler decides, read its row in `plan decisions --json`; when `unfinished` names two or more slices, tell the user at once and keep running. A reconciler edits the slice files for a decision it makes under the grant and returns any change to `plan.md`'s prose, which you have a `slice` subagent apply as a revision the grant authorizes, with no approval step. Escalate a recurring unresolved blocker instead of repeating the same repair.

After the reconciler returns:

- send a repaired or revised slice back to a worker in its worktree before integrating it;
- let a running slice that a decision revises run until its worker reports, then return it to a worker with the revision;
- re-dispatch the integrator, or retry `plan start`, once the reconciler records a new target tip with `plan target-tip`;
- add a returned new slice as in Finish.

Relay escalations to the user and pause every slice an escalation lists as affected under any of its options. First run `plan block <ID> --reason <the input it awaits>` for each such slice that is ready or in progress. A worker still running on a paused slice finishes and reports, and its committed work waits in its worktree for integration; worktrees hold the recovery state, so unaffected slices keep running and integrating, one shared-prose writer at a time. Once the running workers of the paused slices have reported, since each owns its checkpoint until then, have a subagent record each paused slice's next action in `checkpoints/<ID>.md` (`plan start` keeps that file for a slice not yet started); then start other eligible work. Pass the user's answer to a reconciler once the workers of the slices it affects have reported: it records the answer with `plan decide`, updates the next action in `checkpoints/<ID>.md` of each paused slice the answer affects, and returns the approved revision without editing slice files or `plan.md`. Once every running slice whose files the revision changes has reported, dispatch a subagent to read and follow `../slice/SKILL.md` directly, as workers read `next-slice`, and apply every slice-file and `plan.md` change of that revision, passed to it as an approved revision, passing `--note "R<n>: <summary>"` to each `plan slice add|edit`, before dependent slices continue; one approved revision yields one `slice <ID> revised` entry per changed slice. Then return each paused slice with `plan resume <ID>`: a slice with a worktree goes back to in progress there, and you return it to a worker in that worktree, or to an integrator when its committed work needs no change; one that never started goes back to ready for `plan next`.

## Finish

When `plan status` shows every slice complete, dispatch a subagent to check the agreed outcomes and required integration evidence on the target branch, and route its gaps to a reconciler. Have a subagent add each new slice the reconciler returns by following `../slice/SKILL.md`, passing it as authorized: a repair covers an agreed outcome, and a decision's slice is one the grant or the user's answer authorizes. Then inspect again for its constraints and resources and run it like any other. Finish once the check finds no gaps, with a final report of the plan path, completed work, landed revisions, unresolved blockers, and the worktrees `plan status` still lists for paused slices. When nothing can proceed while input is pending, stop and report the paused state instead of completion; that stop keeps the grant.

After an autonomous run, meaning any run in which a grant was recorded, including one granted partway through, the report lists the `pending-review` decisions, costliest to undo first. `plan decisions --pending` gives the indexed ones in that order. When `log.md` has an ``imported by `plan import` `` entry, have a subagent report the `pending-review` decisions `log.md` records before it, which the index lacks, leaving out those a later `approved` decision names as the one it approves, and merge them in by their recorded undo cost. Then list the escalations that still await input.

For a completed run, assemble the final report; when a grant is recorded, run `plan revoke` before delivering it and say the grant ended.
